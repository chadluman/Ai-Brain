# COITB JavaScript Professional Developer Exam Blueprint

Verified against official COITB pages on 2026-11-02. Recheck immediately before a study plan, mock exam, registration decision, or claim about current exam logistics.

## Credential and Exam Summary

- Official credential name: **JavaScript Professional Developer Certification**.
- Published length, item count, and passing score, from COITB's own full-stack article: **90 minutes, 90 items, 73%**.
- Delivery described on COITB badge pages generally: online remote proctoring or an authorized test center; language listed as English.
- Position in the COITB pathway: the second credential in COITB's recommended full-stack sequence, after HTML-CSS Web Designer and before ReactJS Framework Developer.

## What Is NOT Verified Here

No COITB exam-outline page for this certification was located on 2026-11-02 through COITB's site search, so this blueprint does **not** claim official domain names, domain weights, or question counts by domain. The curriculum areas in the companion curriculum file are preparation topics drawn from the language itself, not a reproduction of a COITB outline. Do not present them as official domains, and do not fill the gap with weights borrowed from another vendor's JavaScript exam.

## Exam-to-Curriculum Interpretation

- Cover every curriculum area. Allocate practice by measured learner weakness, not by an invented weight.
- Teach code reading as well as code writing. A multiple-choice and scenario-based exam can test values, scope, control flow, DOM results, asynchronous outcomes, and error handling without requiring a live editor.
- Pair each area with a working project artifact. Correct answers without the ability to write, run, and debug a script are insufficient practical evidence.
- Teach accessibility as a cross-cutting expectation: interactive behavior must remain keyboard-usable and announced correctly, even though no separate accessibility domain is claimed here.
- Treat frameworks as out of scope for this exam's preparation topics. React has its own COITB credential; do not let framework setup displace language fundamentals here.

## Local Readiness Heuristic

This is a teaching heuristic, not a COITB policy or score prediction:

- complete at least three original mixed practice sets under time pressure;
- score at least 85% on each of the last two sets;
- score at least 75% within every curriculum area rather than relying on strength in one area to conceal a gap;
- explain the rationale for corrected answers without memorizing wording;
- complete the curriculum capstone acceptance criteria and diagnose at least one injected syntax, scope, DOM, asynchronous, and error-handling defect.

If the exam date is near, prioritize high-weakness areas. If time permits, repair prerequisite gaps before increasing question volume.

## Standards Cross-Check

- [ECMAScript Language Specification](https://tc39.es/ecma262/) is the normative source for language behavior.
- [MDN Web Docs: JavaScript](https://developer.mozilla.org/en-US/docs/Web/JavaScript) is a practical reference for syntax, built-ins, and browser APIs; it does not define exam scope.
- [WHATWG HTML Living Standard](https://html.spec.whatwg.org/) and [DOM Standard](https://dom.spec.whatwg.org/) define the document and event behavior JavaScript interacts with.
- [WCAG 2.2](https://www.w3.org/TR/WCAG22/) is the current W3C Recommendation used by the vault as an accessibility-planning baseline when a project supplies no different requirement.

These sources are cataloged with their limits in the vault's [Source Registry](../../../20-Catalog/Sources/Source%20Registry.md).
