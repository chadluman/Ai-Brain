# COITB Certification Pathway Curriculum

Use this as an adaptable multi-credential plan, not a fixed calendar. Each credential is taught through its own preparation skill; this curriculum sequences those skills and sets the gates between them.

## Learner Assumptions

- The learner's goal determines the sequence: a front-end goal follows the developer sequence; a back-end goal adds Python after MySQL or alongside it; a sales goal places Technical Sales by career need, not by developer dependency.
- Practice content and assets are original, licensed, or explicitly permitted.
- Exam preparation and certification are separate outcomes. Completing this pathway does not guarantee any passing score.

## Final Observable Outcome

The learner can state, for each credential they attempt, why it comes in that order, what its readiness gate was, what evidence met it, and what carries forward to the next credential.

## Stage 0 — Goal and Baseline

- **Outcome:** A written goal, a baseline diagnostic for the first credential only, and a sequence with reasons.
- **Demo:** Work through one learner goal and show how it changes the sequence.
- **Guided task:** Record the learner's goal, available time, prior projects, and first-credential diagnostic.
- **Independent task:** Write the sequence in the learner's own words, with a reason per credential.
- **Verification:** the sequence is justified by dependency and goal, not by the order credentials happen to be listed on a page.

## Stage 1 — Front-End Foundation (HTML → JavaScript → React)

- **Outcome:** The learner completes the HTML, JavaScript, and React preparation skills in order, with a readiness gate before each exam.
- **Guided task:** After each credential, record demonstrated evidence, remaining weaknesses, and project carry-forward notes.
- **Independent task:** Before the next credential, complete that credential's diagnostic and repair prerequisite gaps.
- **Verification:** no exam date is committed until that credential's own readiness heuristic is met.

## Stage 2 — Back-End Expansion (MySQL, then Python as an Add-On)

- **Outcome:** The learner completes the MySQL preparation skill, then Python if their goal calls for it, with a readiness gate before each exam.
- **Guided task:** Decide whether the learner's project gains a real data layer, or whether MySQL and Python are better served by separate projects.
- **Independent task:** Write the back-end plan in the learner's own words, with a reason for including or deferring Python.
- **Verification:** the back-end project uses synthetic data only and demonstrates safe data handling, not just correct answers.

## Stage 3 — Add-Ons by Goal (GPT Professional, Technical Sales)

- **Outcome:** The learner places each add-on credential by career goal, not by developer dependency, and completes its own preparation skill.
- **Guided task:** For each add-on, record why it is included, when it is attempted, and what it does not replace.
- **Independent task:** Write the add-on plan in the learner's own words, including the verification status of its blueprint.
- **Verification:** no add-on is presented as a substitute for a core credential, and no unverified logistics are quoted for GPT Professional or Technical Sales.

## Stage 4 — Review and Replanning

- **Outcome:** A pathway review that updates the sequence, gates, and next action after every credential, delay, or failed attempt.
- **Guided task:** After each credential, update the sequence and record what changed and why.
- **Independent task:** If a credential is delayed or failed, rewrite only the affected part of the plan.
- **Verification:** the plan always states the next credential, its readiness gate, and the next study action, with nothing left as a vague intention.
