# COITB HTML-CSS Web Designer Exam Blueprint

Verified against official COITB pages on 2026-10-22. Recheck immediately before a study plan, mock exam, registration decision, or claim about current exam logistics.

## Credential and Exam Summary

- Official credential name: **HTML-CSS Web Designer Certification**.
- Published length: **90 minutes**.
- Published item count: **90**.
- Published passing score: **75% or higher**.
- Recommended experience: **0–6 months** of hands-on HTML/CSS practice.
- Delivery described by the badge page: online remote proctoring or an authorized test center; language listed as English.

Official format wording is inconsistent as of verification: the [exam outline](https://www.coitb.org/certification-resources/exam-outlines/html-css-web-designer-outline) says **multiple-choice**, while the [badge page](https://www.coitb.org/certification-resources/badges/html-css-web-designer) says **multiple-choice and scenario-based items**. Prepare learners for both code-reading and applied scenarios, and recheck rather than resolving the discrepancy by assumption.

## Published Domains

| Domain | Weight | Published question count | Published objectives |
|---|---:|---:|---|
| HTML Structure | 20% | 18 | Identify the basic document structure; use essential organizational tags; create hyperlinks and embed images |
| CSS Basics | 25% | 23 | Apply styles; use classes and IDs; implement color, fonts, and alignment |
| Layout Techniques | 20% | 18 | Use the box model; apply Flexbox and Grid |
| Responsive Design | 20% | 17 | Create layouts with media queries; design adaptable interfaces for screens |
| HTML Forms | 10% | 9 | Create simple forms; implement validation techniques |
| Advanced CSS | 5% | 5 | Use transitions and animations; implement preprocessors such as Sass; use CSS variables |

The published question counts total 90. Treat the weights and counts as a planning baseline, not a promise that every future form uses the same distribution.

The badge page also emphasizes semantic HTML for headings, sections, forms, and media; maintainable selectors and specificity; responsive Flexbox, Grid, and media queries; basic accessibility and ARIA; consistent typography, color, and spacing; and multi-section landing pages or simple sites. These statements clarify intended competence but do not add a separately weighted domain.

## Exam-to-Curriculum Interpretation

- Cover every published objective. Allocate practice by both official weight and measured learner weakness.
- Teach code reading as well as code writing. A multiple-choice exam can test cascade, specificity, computed result, box size, layout behavior, selector matching, form attributes, and responsive outcomes without requiring a live editor.
- Pair each domain with a working project artifact. Correct answers without the ability to build and debug a page are insufficient practical evidence.
- Teach accessibility as a cross-cutting expectation even though it has no separate published weight.
- Treat Sass as a concept inside the 5% Advanced CSS domain. Explain variables, nesting risks, compilation, and when native CSS is sufficient; do not make package installation a prerequisite.

## Local Readiness Heuristic

This is a teaching heuristic, not a COITB policy or score prediction:

- complete at least three original mixed practice sets under time pressure;
- score at least 85% on each of the last two sets;
- score at least 75% within every domain rather than relying on strength in CSS Basics to conceal a gap;
- explain the rationale for corrected answers without memorizing wording;
- complete the curriculum capstone acceptance criteria and diagnose at least one injected HTML, cascade, layout, responsive, form, and animation defect.

If the exam date is near, prioritize high-weight weak domains. If time permits, repair prerequisite gaps before increasing question volume.

## Standards Cross-Check

- [WHATWG HTML Living Standard](https://html.spec.whatwg.org/) is the normative living source for HTML behavior and semantics.
- [CSS Snapshot 2026](https://www.w3.org/TR/css-2026/) records CSS specification composition and stability but does not prove browser support.
- [CSS Flexible Box Layout Level 1](https://www.w3.org/TR/css-flexbox-1/) and [CSS Grid Layout Level 2](https://www.w3.org/TR/css-grid-2/) define the relevant layout models; verify selected features in target browsers.
- [Media Queries Level 5](https://www.w3.org/TR/mediaqueries-5/) is a Working Draft at this review date. Teach broadly supported behavior first and verify newer media features.
- [WCAG 2.2](https://www.w3.org/TR/WCAG22/) is the current W3C Recommendation used by the vault as an accessibility-planning baseline when a project supplies no different requirement.

These sources are cataloged with their limits in the vault's [Source Registry](../../../20-Catalog/Sources/Source%20Registry.md).
