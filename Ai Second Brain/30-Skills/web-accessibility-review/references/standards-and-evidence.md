# Accessibility Standards and Evidence

Verified 2026-10-21. Recheck before a new compliance baseline or major release.

## Source Roles

- [WCAG 2.2](https://www.w3.org/TR/WCAG22/) is the versioned W3C Recommendation used for normative web-content accessibility requirements.
- [What's New in WCAG 2.2](https://www.w3.org/WAI/standards-guidelines/wcag/new-in-22/) explains the nine criteria added since WCAG 2.1 and notes that 4.1.1 Parsing was removed.
- [WAI-ARIA 1.2](https://www.w3.org/TR/wai-aria-1.2/) normatively defines accessibility roles, states, and properties.
- [ARIA Authoring Practices Guide](https://www.w3.org/WAI/ARIA/apg/) provides patterns, keyboard interaction, accessible-name guidance, and examples.
- [APG introduction](https://www.w3.org/WAI/ARIA/apg/about/introduction/) explicitly distinguishes WCAG and ARIA as normative standards from APG as informative guidance.
- [W3C `aria-practices` repository](https://github.com/w3c/aria-practices) is the official source repository linked from the APG publication. Treat examples as illustrative, not as automatically production-ready components.

## Evidence Rules

- Cite the fixed WCAG 2.2 URL when a decision depends on that exact version.
- Cite the relevant success criterion, not only “WCAG compliant.”
- Separate conformance requirements from techniques and example patterns.
- Record the tested content, states, user journeys, browser/device combinations, input methods, and assistive technologies.
- An automated result can prove that a particular detectable rule passed or failed under its test conditions; it cannot establish complete conformance.
